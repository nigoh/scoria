# 本家 deb への上流フィードバック

deb をテンプレート複製（ADR-0003）またはプラグイン（ADR-0008）で使っていて気づいた、
**土台そのものへの改善**を本家へ届ける。同一リポジトリ内の学び（気づきカード、ADR-0002）ではなく、
「deb 自体をこう良くしたい」を送る導線。

## 上流リポジトリ

- 既定の送信先: **`nigoh/deb`**
- このリポジトリを fork して自分の土台にした場合は、上の値を自分の土台リポジトリに読み替える
  （fork 時はこの SKILL.md の送信先を書き換える）。

## 手順

### 1. 種別と内容を整理する

`$ARGUMENTS` と会話から、次を1つのフィードバックにまとめる:

- **種別**: 機能要望 / 摩擦・不具合 / 気づき（再利用できるパターン）のいずれか
- **要約**: 一言でのタイトル
- **本文**: 何を・なぜ（どのプロセス段階・どの機構で困ったか、どう改善したいか）
- **関係する機構/段階**: CLAUDE.md / rules / skills / agents / workflows / hooks / docs/process のどれか、
  または V字のどの段階か
- 可能なら再現・根拠（deb のバージョンやコミット、`git rev-parse HEAD` があれば添える）

### 2. サニタイズ（重要）

- **アプリ固有の情報・秘密情報を含めない**。deb（土台）に関する内容に限定する
- 具体的なコード片を載せる場合も、業務ロジックや機密を含めないこと

### 3. 提示して確認する（外向き発信のため必須）

- 起票する**イシューのタイトルと本文をユーザーに提示し、送信してよいか確認する**（誤送信・情報漏れ防止）
- 確認が取れるまで起票しない

### 4. 起票する

利用可能な GitHub ツールで、上流リポジトリにイシューを作成する（`template-feedback` ラベルを付ける）:

- gh CLI: `gh issue create --repo nigoh/deb --label template-feedback --title "..." --body "..."`
- GitHub MCP: 対応する issue 作成ツールで repo=nigoh/deb を指定
- どちらも使えない場合は、事前入力済みの新規イシュー URL を提示する:
  `https://github.com/nigoh/deb/issues/new?labels=template-feedback&title=<URLエンコード>&body=<URLエンコード>`
  （本家のイシューテンプレート `template-feedback` に沿った本文にする）

### 5. 結果を返す

作成したイシューの URL（または事前入力 URL）をユーザーに返す。ラウンドの振り返り（`/round close`）で
土台に効く気づきが出たら、このスキルで本家へ送るとよい。
