# ポストモーテム（予防活動）

障害を「二度と起こさない」ための手順。IPA の障害事例からの再発防止・代用特性展開を翻訳
（`docs/process/verification.md`）。成果物は `docs/process/templates/postmortem.md` を雛形に起こす。

## 1. 事実の把握

- 何が起きたか（事象）、影響範囲、検知経緯を時系列で書く（推測と事実を分ける）
- 再現手順を特定する

## 2. 原因分析

- **なぜを繰り返す**（なぜなぜ分析）で根本原因まで掘る。表層の症状で止めない
- 「作り込み原因」（なぜ欠陥が入ったか）と「流出原因」（なぜ検知で止まらなかったか）を分けて分析する

## 3. 再発防止テストを先に書く（red→green）

- 根本原因を突く**再発防止テストを先に書き、red を確認**する（`test-engineer` に委譲可）
- 修正を入れて green を確認する。テストは `Verifies:` で関連要件があれば結ぶ

## 4. 代用特性への展開・規約反映

- 守るべき品質特性を、観測できる代用特性（テスト・チェック・メトリクス）に落とす
- 原因が**構造的**（同種の欠陥が再発しうる）なら、恒久対策として規約へ反映する:
  - 実行時に機械的に防げる → `.claude/hooks/`（+ `scripts/test-hooks.sh` にケース追加）
  - 判断を伴う → `.claude/rules/` または `code-reviewer` の観点
  - 手順の問題 → 該当 skill / `docs/process/`
- 学びは「気づきカード」イシュー（ADR-0002）として残す

## 5. 確認

`bash scripts/check.sh` で緑を確認する。再発防止テストが恒久的にゲートに残ることを確かめる。
