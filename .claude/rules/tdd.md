# テスト厳格度の規約（実行コードを編集中に自動ロードされる。ADR-0013）

決定の背景・選択肢は ADR-0013、詳細は `docs/process/verification.md`／テーラリングは `docs/process/lifecycle.md`。
アプリ側のソース（`src/**` / `e2e/**`）も対象。フロントの層別規約は `.claude/rules/frontend.md`。

## いつどのテスト戦術を使うか（重要度×規模のテーラリングに従う）

- **純粋ロジック関数・重要度「高」**（認証・課金・個人情報・マイグレーション・公開 API）:
  **test-first**。①失敗するテストを書いて実行し**赤を実際に観測**する → ②最小実装で緑 → ③リファクタ。
  赤→緑は**1セッション内で連続**して行う（赤を残したままコミット/handoff しない。Stop フックが全緑を要求するため）。
- **ガード等の高重要度コンポーネント**（`.claude/hooks/*`, guard 系）: **契約/表テストを先に**書く
  （「保護 ref に届く全 push 形はブロック」のように振る舞いの契約を列挙してから実装/修正）。
- **エッジ多発コード**（パーサ・locale/`date`/`sort`・ツール依存・並列・破損入力）:
  **敵対的/property テストを必須**とする（境界値・直交表・状態遷移＋ツール欠落/ロケール/並列の再現）。
  このリポジトリの欠陥はここに集中する（`knowledge/insights/2026-07-20-bug-hunt.md` / `2026-07-23-mape-hardening.md`）。test-first より優先。
  - **二重バックエンド等価性**: 同一処理を複数経路で実装する箇所（例 jq ⇄ python3）は、片経路のツール欠落
    再現だけでなく、**同一入力で両経路が同一 verdict/出力を返す**ことを（片方ずつ隠して）検査する。
    非オブジェクト/不正UTF-8/空白のみ行・null 描画・正規化差で経路が食い違うと、**インストール済みツール
    次第でゲート結果が変わる非決定論**になる（Round 6 の最大の欠陥源）。
  - **フェイルセーフの「向き」**: 安全機構（暴走停止・safe-state・guard）は情報欠落（パーサ不在・
    detached HEAD・判定不能・stale な状態ファイル）で **fail-closed（停止/unsafe）** に倒すことをテストで固定する。
    fail-open（許可）は安全境界の侵食。「判定不能＝安全側で止める」を既定に。
- **自明変更（typo・明白な1行）・重要度低**: test-first は省略可（既存の「再発防止テストのみ」に一致）。

## 規律

- **テストの合格条件を弱めない**: 緑にするためにアサーションを削る・skip を乱用する・タイムアウトを
  安易に延ばすことを禁止（test-engineer と同文）。headless で skip したテストを「検証済み」と数えない。
- **順序（red-first）は機械強制しない**（自律エージェントには検証不能なため偽装しない）。機械強制は
  **結果**のみ: 要件被覆（`check-traceability.sh` の `Verifies:`）と、スタック導入後のテスト緑・網羅率
  （`/stack-init` が `check.sh` に追記。ADR-0004＝弱めない・単一入口・フックやCIに直書きしない）。
- 省略した戦術は PR/イシューに「なぜ省略したか（規模・重要度）」を1行残す。
- 仕上げに `bash scripts/check.sh` で全体の緑を確認する。
