# 要件定義の規約（このファイルは要件成果物を編集中に自動ロードされる）

プロセス詳細は `docs/process/requirements.md`、ID 体系は `docs/process/traceability.md`。

- 機能要件は `REQ-<領域>-<3桁>`、非機能要件は `NFR-<分類>-<3桁>` で採番（ID は再利用しない）。
- **すべての要件に検証可能な受入基準**（Given/When/Then 等）を付ける。基準なき要件を残さない。
- **NFR は7カテゴリ（性能・信頼性・使用性・セキュリティ・保守性・移植性・運用性）を必ず一巡**し、
  対象外は「対象外」と明記する（検討漏れと区別）。
- 各要件に責任者（要求元・実装責任・検証責任）と優先度を記録する。
- 要件の追加・変更・削除は ID を明示し、理由・影響（対応 DES/TEST）を記録する（変更管理）。
- 対応テストは `Verifies: <要件ID>` で結ぶ（`check-traceability.sh` が被覆を検証する）。
