# 検証：予防活動・検知活動・定量品質

ADR-0007 の詳細。IPA の「予防活動／検知活動」「レビューとテストの欠陥検出戦略の統合」
「テスト網羅性の高度化」「定量的品質マネジメント」を翻訳。

## 予防活動（欠陥を作り込まない）

- **テスト駆動（新規実装の red→green→refactor。ADR-0013）**: 純粋ロジック関数・重要度「高」の新規実装は、
  **失敗するテストを先に書いて赤を実際に観測** → 最小実装で緑 → リファクタ、を標準リズムとする。
  赤→緑は1セッション内で連続して行う（Stop フックが全緑を要求するため赤を残さない）。「順序」は文化的規律、
  「結果」（被覆・緑・網羅率）は `check.sh`／`check-traceability.sh` が機械強制。戦術の選び分け（test-first／
  ガードの契約テスト先行／エッジ多発コードの敵対的・property テスト必須）は ADR-0013 と `.claude/rules/tdd.md`。
- **障害からの再発防止**: 不具合が出たら `/postmortem` で原因分析 → **再発防止テストを先に書く（red→green）**
  → 原因が構造的なら規約（rules/hooks/CLAUDE.md）へ反映する（テスト駆動の一事例）。
- **代用特性の考え方**: 「守りたい品質特性」を、観測・検証できる具体的な代用特性（テスト・チェック・
  メトリクス）に落とす。例: 「決済の信頼性」→「二重課金を防ぐ冪等性テスト」。
- 学びは「気づきカード」（ADR-0002）として蓄積し、恒久的な予防に昇華する。

## 検知活動（欠陥を早く見つける）— レビューとテストの統合

同じ欠陥を二度見ないよう、レビューとテストの役割を分担する:

| 手段 | 主に担う欠陥 | 入口 |
|---|---|---|
| レビュー | 設計の妥当性、規約違反、可読性、要件との整合、テストの十分性 | `code-reviewer`（レビュー観点を内蔵） |
| テスト | 動作の正しさ、境界・異常系、回帰 | `/test-design` + `test-engineer` |

- レビューは「テストで見つけにくい欠陥」に集中する（設計・意図・整合）。
- テストは「レビューで見つけにくい欠陥」に集中する（実行時の振る舞い・網羅）。

### レビュー技法（IPA 3.2.2 の翻訳）

- **観点駆動・チェックリスト駆動**で読む（思いつきで読まない）。観点は `code-reviewer` に内蔵し、
  領域固有の観点は `.claude/rules/` に足す。
- **欠陥は工程間で持ち越す**前提で臨む。上流（要件・設計）で作り込んだ欠陥は下流ほど修正コストが
  上がるため、上流レビューを厚くする（フロントローディング）。前工程で検出しきれなかった欠陥は
  次工程のレビュー観点に引き継ぐ。
- 対象の重要度（`lifecycle.md` の軸1）が高いほどレビューの形式度を上げる（複数観点・独立の目）。

## テスト網羅性の高度化（`/test-design`）

IPA 第6章の翻訳。テストは行き当たりばったりでなく、観点 → アーキテクチャ → 技法の順に設計する:

1. **テスト観点の抽出**: 何を確かめるかの軸（機能・境界・状態遷移・組み合わせ・異常系・非機能）を洗い出す
2. **テストアーキテクチャ設計**: 観点をテストレベル（unit/integration/system/acceptance）へ割り付ける
3. **技法の適用**:
   - **同値分割・境界値分析**: 入力空間を代表値で被覆
   - **直交表・ペアワイズ**: 組み合わせ爆発を、2因子間網羅で圧縮（全網羅せず欠陥検出力を保つ）
   - **状態遷移テスト**: 状態と遷移を被覆
   - **シナリオテスト**: 現実の利用フローで結合的に検証（ピンポイント）

## 定量品質（段階ゲートの参考指標）

「弱めない」（ADR-0004）対象。計測可能になったものから段階ゲートに接続する:

| 指標 | 意味 | 目安 |
|---|---|---|
| テスト網羅率 | コード／要件のうちテストされた割合 | スタックごとに閾値を `check.sh` に設定 |
| 要件被覆率 | 対応テストを持つ要件の割合 | 100%（`check-traceability.sh` が担保） |
| 残存欠陥 | 既知・未修正の不具合数と重篤度 | ERROR 級を残してリリースしない |
| レビュー指摘密度 | 変更規模あたりの指摘数 | 異常値は設計の見直し signal |

指標は「数値を追う」ためでなく「異常に気づく」ために使う。過剰計測はしない（ADR-0007 の再検討トリガー）。
