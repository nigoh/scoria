# 0027: マネタイズの主軸を「AI 設計フリーミアム × BYOK」とし、AI はブロックを設計し組み立ては決定論に任せる

- Status: Accepted
- Date: 2026-08-02
- Deciders: リポジトリオーナー

## Context（背景）

Scoria を収益化したい。しかし現状は課金の理由を作れない構造にある。

- 生成が決定論テンプレートで、素の Claude に「スキル書いて」と頼めば無料で得られるものと差がない
- 完全クライアントサイドでアカウント概念がなく、課金対象を識別する土台がない
- 運営者はサーバー管理・API 原価・個人情報の取扱いを**極力負いたくない**（確認済みの制約）

検討した事業モデルは4つ: (A) AI 生成フリーミアム、(B) 買い切り Pro、(C) テンプレートマーケット
プレイス、(D) 機関ライセンス。C はユーザー基盤が要るため時期尚早、D は営業が要るため後回し。

## Decision（決定）

**A を主軸に、運用を軽くするため BYOK（Bring Your Own Key）で実装する。**

1. **有料価値は「AI 設計」**: 研究内容の自由記述から、学術特化のシステムプロンプトで拡張を設計する。
   素の Claude との差は、(a) Claude Code 拡張仕様の知識を埋め込んだプロンプト、(b) 応答の検証と
   正規化、(c) ウィザード・編集・エクスポートへの統合
2. **API キーは利用者が持ち込む（BYOK）**: キーはブラウザの localStorage にのみ保存し、送信先は
   Anthropic API のみ。運営側の API 原価ゼロ・サーバーゼロ・個人情報の預かりゼロ
3. **AI はブロックを設計し、ファイルの組み立ては既存の決定論ジェネレータが行う**。
   AI の応答は `{name, description, blocks[]}` に限定（structured outputs で強制）し、
   frontmatter・パス・ファイル構成はテスト済みの `generator.ts` が組み立てる。
   これにより「AI が仕様違反のファイルを吐く」事故が構造的に起きない
4. **課金はライセンスキー方式を後続ラウンドで足す**: Stripe Payment Links → Webhook Worker →
   キー発行 → クライアント検証。Stripe 開設は運営者の作業なので本ラウンドの範囲外。
   それまで AI 設計は**無料ベータ（BYOK）**として公開し、利用実態を課金設計の入力にする

技術詳細: 公式 `@anthropic-ai/sdk`（`dangerouslyAllowBrowser`）、モデル既定 `claude-opus-5`
（設定で sonnet/haiku に変更可）、structured outputs（`output_config.format`）、
`stop_reason: "refusal"` の明示ハンドリング。

## Options Considered（検討した選択肢）

### 案1: BYOK + ライセンスキー（採用）

- 長所: 運用コストほぼゼロで A の価値を出せる。API 原価・鍵管理・個人情報を負わない。
  Payment Links + 小さな Worker だけで課金導線が完成する
- 短所: 「API は自分持ちなのに何に金を払うのか」の説明責任が生じる（→ 売るのは学術特化の
  設計プロンプト・検証・統合・継続更新というソフトウェア価値）。キー入力の敷居がある

### 案2: マネージド API（運営者のキーで代理呼び出し + 従量課金）

- 長所: 利用者はキー不要で敷居が最も低い。課金の理由が自明（原価がある）
- 短所: バックエンド・認証・不正利用対策・従量集計・原価変動リスクをすべて負う。
  「極力軽く」の制約に反する

### 案3: 買い切り Pro のみ（AI なし）

- 長所: 実装最小
- 短所: 売る物が現状の静的機能のみで、素の Claude に対する優位を作れない。天井が低い

## Consequences（結果）

- `src/lib/ai/` が新設され、プロンプト構築・応答検証は純粋関数としてテストされる（ADR-0013）
- 要件は `docs/requirements/ai-design.md` に REQ/NFR として管理し、`Verifies:` で追跡する
- キーはローカル保存のため、共有 PC では利用者自身の管理に委ねる（設定画面に明示する）
- ベータ→有償化の切替時は、価格・ライセンス検証 Worker・特商法表記を新 ADR で決める
- **再検討のトリガー**: BYOK の敷居で利用が伸びない場合、案2（マネージド API の従量課金）を
  上位プランとして追加するか判断する
