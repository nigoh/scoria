# 0015: MAPE-K の項目隔離（per-item quarantine）と有界なブレーカー自己修復

- Status: Proposed
- Date: 2026-07-22
- Deciders: （PR レビュアー）

## Context（背景）

ADR-0010 のサーキットブレーカーは「同一項目 red 2回 / 末尾連続 red / 直近window の red 多発」で
Execute を **全停止**（exit 3）させ、手動 `reset` まで凍結する。ADR-0014 の診断どおり、**1つの毒項目**が
繰り返し赤になると Execute 全体が止まり、健全な他候補まで進まない（自己修復の欠如）。
また同一項目 red 回数は台帳全体の単調カウントで、緑が増えても減らないため、一度超えると
`reset` するまで永久に tripped のままになる。ADR-0010 は main マージ済みで編集不可のため、本 ADR で
**拡張**する（supersede しない）。ブレーカーの「暴走を止める」責務は維持する。

## Decision（決定）

ブレーカー意味論を **弱めずに拡張** する。追加のみ。

- **項目隔離（quarantine）**: `circuit-breaker.sh quarantine <item> [reason]` が BACKLOG.md の
  「## ブロック中」へ item を追記する。`analyze.sh` は隔離済み候補を**再提案しない**（step 2 で skip）。
  Execute（`mape-execute`）は同一項目が上限赤に達したら、全停止の前に当該項目を隔離して他項目へ進む。
- **有界な自己修復（同一項目トリップの自動クリア）**: `status` は、同一項目トリップの原因 item が
  **隔離済み（＝再提案されない＝再発しないと証明済み）**なら、その理由を判定から除外して ok を返す。
  末尾連続 red・直近window red（＝真の暴走の全体指標）は**隔離では絶対に解除しない**。手動 `reset` は不変。
- **観測**: 初回トリップ時刻を `mape/state/breaker.tripped_at` に記録（通知・任意 cooldown 用）。
  任意の `MAPE_CB_COOLDOWN_H`（既定 0=無効）は、隔離クリアに最小 dwell を課す保守的ダンパで、
  **回復を早める方向には決して働かない**（暴走停止も緩めない）。

## Options Considered（検討した選択肢）

### 案1: 項目隔離＋隔離ゲート付き同一項目トリップの自動クリア（採用）

- 長所: 毒1件で全停止する欠陥を解消しつつ、全体暴走指標（連続/窓）は最終防壁として不変。決定論 Bash の
  小増分で test-first 可能。ADR-0010/0011 の原則（1周1件・PR まで・弱めない）を保つ。隔離＝再発しない証明が
  クリアの前提なので、安全側でのみ回復する。
- 短所: BACKLOG に新セクションが増える。隔離解除は現状手動（BACKLOG 編集）。

### 案2: ブレーカーに時間 cooldown を入れ、一定時間で全種トリップを自動解除（不採用）

- 長所: 完全放置でも自然回復。
- 短所: **暴走を時間だけで解除**し得る（原因未隔離のまま再開＝安全境界の侵食）。runaway 停止の意味を弱める。

### 案3: 何もしない（従来どおり全停止＋手動 reset）（不採用）

- 長所: 最も単純。
- 短所: ADR-0014 の実診断（毒1件で凍結・同一項目カウントが永久）を放置。自己修復が進まない。

## Consequences（結果）

- 得るもの: 毒項目を隔離して周回を継続でき、原因が証明的に隔離されたときだけ同一項目トリップが自動回復する
  自己修復。全体暴走の最終防壁と手動 reset は不変。
- 失うもの: 隔離解除は手動。BACKLOG に運用セクションが増える。
- **再検討のトリガー**:
  - 隔離が頻発（＝提案の質が低い）なら Analyze 設計を見直す新 ADR。
  - 自動解除が誤って暴走を再開させたと監査で判明したら、当該増分を revert し設計を見直す。
  - 隔離解除の自動化（例: green 実績や TTL）が要るなら新 ADR で判断する。
