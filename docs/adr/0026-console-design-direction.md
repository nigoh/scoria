# 0026: 画面デザインの方向を「コンソール」に定め、デザイントークンを作り直す

- Status: Accepted
- Date: 2026-08-02
- Deciders: リポジトリオーナー

## Context（背景）

Scoria の見た目は shadcn/ui の初期テーマ（青 `hsl(217 91% 60%)` × 白・角丸 8px）のままで、
Scoria がどんな道具なのかが一切表れていない。実害も出ている。

- ビルダーのステップ表示が「拡張タイ／プ」のように折り返して崩れる（丸バッジ＋ラベルの横並びが
  幅に耐えない）
- 生成物は Claude Code の設定ファイル（YAML frontmatter + Markdown）なのに、画面には等幅書体が
  ほぼ使われておらず、何が出てくるのか画面から想像できない
- 角丸・淡い影・大きな余白の組み合わせが、設定項目の多い Step 3 で情報密度を圧迫している

4つの方向（索引カード／コンソール／標本図版／スコリア）を実際の画面として組んで比較し、
そのうえで方向を1つ決める。

## Decision（決定）

**「コンソール」方向を採用する。** 生成した拡張が動く場所（ターミナル）に画面を寄せ、
画面の見た目と生成物を地続きにする。

- **配色**: 藍墨 `#0e1418` を地に、琥珀 `#e8a33d` を**唯一の主アクション色**、
  シアン `#5fb3c4` を識別子・パス・副次的な強調に使う。純黒を使わない（長時間の作業で目が疲れる）
- **角丸を 0 にする**（`--radius: 0`）。罫線でブロックを区切り、影に頼らない
- **書体は等幅を既定にする**。`--font-mono`（JetBrains Mono、導入済み）を body の既定に置き、
  日本語は和文ゴシックへフォールバックする。長い日本語の説明文だけ `--font-sans` を明示する
  （和文等幅は同梱していないため、Latin=等幅／和文=ゴシックの混植を前提に組む）
- **ダークを主、ライトを従とする**。ライトは反転ではなく「印刷したリスト」として別に設計し、
  琥珀とシアンは明地で読める明度に落とす
- **`--signal` トークンを追加する**。shadcn の `--accent` は本来ホバー面の色なので、
  そこに強調色を入れない（現状はここに青が入っていて、ホバーが青く光る原因になっている）

## Options Considered（検討した選択肢）

### 案1: コンソール（採用）

- 長所: 情報密度を最も上げられ、Step 3 のような項目の多い画面が破綻しない。YAML frontmatter を
  そのまま見せられる。実装コストが最小（既存コンポーネントの色と角丸を落とすだけで骨格が出る）
- 短所: ターミナルに馴染みのない研究者には敷居が高く見える

### 案2: 索引カード（図書目録の物質感）

- 長所: 学術研究の道具であることが一目で伝わる。分類番号が第二の手がかりになる
- 短所: 紙の比喩は密度を上げにくく Step 3 で窮屈になる。開発者向けとしては柔らかすぎる

### 案3: 標本図版（論文の図版プレート）

- 長所: 説明文が主役の画面で最も読みやすい。キャプションという枠が説明を書く場所を構造で用意する
- 短所: 余白が大きく1画面の情報が減る。縦スクロールが増える

### 案4: スコリア（社名の由来＝火山岩）

- 長所: 名前と見た目がつながりブランドとして記憶される
- 短所: 主張が強く好みが割れる。学術文脈では攻撃的に見えうる

## Consequences（結果）

- `src/index.css` のトークンが正本になる。個別コンポーネントに色を直書きしない
- ステップ表示は丸バッジをやめ、`[1/4] 拡張タイプ` の区画方式にする（折り返し崩れの解消を兼ねる）
- ホームの浮遊する幾何図形アニメーション（`--animate-geo-float-*`）はこの方向と噛み合わないため外す
- 琥珀は「次へ」「ZIP ダウンロード」など**一番大事な操作にだけ**使う。使いすぎると効かなくなる
- **再検討のトリガー**: 利用者の中心が「Claude Code をこれから使う研究者」だと分かったら、
  敷居の高さが実害になるので方向を見直す（案3 が次点）
