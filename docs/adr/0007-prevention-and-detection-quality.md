# 0007: 品質は「予防活動」と「検知活動」の二本立てで作り込む

- Status: Accepted
- Date: 2026-07-17
- Deciders: リポジトリオーナー

## Context（背景）

IPA/SEC ガイドブックは、高信頼ソフトウェアの品質保証を **予防活動**（欠陥を作り込まない）と
**検知活動**（作り込んだ欠陥を早期に見つける）に整理する。予防活動では障害事例からの再発防止と
代用特性展開を、検知活動ではレビューとテストの欠陥検出戦略の統合を提唱する。deb に翻訳して取り込む。

## Decision（決定）

品質を二つの活動で作り込み、それぞれを deb の機構に接続する。

**予防活動（欠陥を作り込まない）**:
- 障害・不具合が出たら `/postmortem` スキルで原因分析 → **再発防止テストを先に書く（red→green）** → 必要なら規約（rules/hooks/CLAUDE.md）へ反映する
- 学びは「気づきカード」（ADR-0002）と接続し、恒久的な予防に昇華する

**検知活動（欠陥を早期に見つける）**:
- **レビューとテストは役割分担して統合する**（同じ欠陥を二度見ない）。レビューは設計・規約・可読性・要件整合を、テストは動作の正しさを担う（`docs/process/verification.md`）
- レビュー観点は `code-reviewer` エージェントと `docs/process/verification.md`、テスト設計は `/test-design`（テスト観点・テストアーキテクチャ・直交表/ペアワイズ・シナリオ）に従う
- 定量品質: テスト網羅率・残存欠陥（既知未修正）などの指標を段階ゲートの参考にする（`docs/process/verification.md`）

## Options Considered（検討した選択肢）

### 案1: 予防＋検知の二本立て（採用）

- 長所: 「作り込まない」と「早く見つける」の両輪で、事後修正コストを最小化。IPA の手法体系と整合
- 短所: レビューとテストの役割分担を明文化・維持する必要がある（→ verification.md で一元管理）

### 案2: テスト（検知）のみ

- 長所: 単純
- 短所: 同じ欠陥の再発を防げず、レビューとテストの重複・抜けが生じる

## Consequences（結果）

- `/postmortem` が予防活動の入口、`/test-design` と `code-reviewer` が検知活動の担い手になる
- 定量品質指標は「弱めない」（ADR-0004）対象になり、`scripts/check.sh` の品質ゲートに接続しうる
- **再検討のトリガー**: 定量指標の計測コストが効果に見合わないなら、指標を絞る
