# 0012: リポジトリのライセンスを MIT とする

- Status: Proposed
- Date: 2026-07-20
- Deciders: リポジトリオーナー

## Context（背景）

deb は「コピーして使う土台リポジトリ」である（README・ADR-0003）。"Use this template" や
`git clone` で複製し、派生リポジトリで自由に改変して使うことを前提にしている。
しかしライセンスファイルが無いため、既定では**すべての権利が留保された状態**であり、
複製・改変・再配布が法的に成立しない。土台の目的（再利用）とライセンス不在が矛盾している。

土台の中身は steering（.claude/）・開発規約・品質ゲートのスクリプトであり、特許化されるような
「発明」ではなく、設定・ドキュメント・シェルスクリプトが主体である。

## Decision（決定）

- リポジトリのライセンスを **MIT License** とし、ルートに `LICENSE` を置く。
- 著作権表記は `Copyright (c) 2026 nigoh`。
- 派生リポジトリは、この LICENSE を保持したまま自分の著作権表記を追記/差し替えて使う。

## Options Considered（検討した選択肢）

### 案1: MIT（採用）

- 長所: 最小・最も摩擦が少ない。1ファイルで完結し、複製先は著作権表記を保持/差し替えるだけで済む。
  テンプレート/スターター系の事実上の標準で、利用者の心理的障壁が低い。
- 短所: 明示的な特許許諾条項が無い（ただし本リポジトリは設定・ドキュメント主体で特許リスクが低く、実害は小さい）。

### 案2: Apache-2.0

- 長所: 明示的な特許許諾と特許報復条項を持ち、防御的。企業配布で好まれる。
- 短所: NOTICE ファイルの伝播・変更点の明示など、**複製のたびに定型作業が増える**。
  土台の性質（コピー前提・発明性が低い）に対して過剰で、利用者の摩擦になる。

### 案3: ライセンス無し（現状維持）

- 長所: 追加作業ゼロ。
- 短所: 既定で全権利留保となり、**再利用が法的に成立しない**。土台の目的と真正面から矛盾する。

## Consequences（結果）

- 複製・改変・再配布が法的に明確になり、土台の目的（再利用）が成立する。
- パッケージメタデータ（将来 `/stack-init` で package.json 等を導入する際の `license` フィールド）は
  `MIT` に揃える。
- **再検討のトリガー**: 特許を含む実装成果物を土台自体に取り込む方針に変わったら、Apache-2.0 への
  変更（新 ADR で supersede）を検討する。
