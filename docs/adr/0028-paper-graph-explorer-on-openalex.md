# 0028: 論文グラフ探索は OpenAlex 直呼びで作り、AI 設計への入力口とする

- Status: Proposed
- Date: 2026-08-14
- Deciders: リポジトリオーナー / Claude

## Context（背景）

Connected Papers 型の「引用関係から類似論文をグラフで探す」体験を Scoria に取り込みたい。
制約は ADR-0027 と同じで、サーバー・API 原価・個人情報を運営側が持たないこと。また探索単体では
無料の本家に勝てないため、Scoria の中核（AI 設計 → 拡張生成）に接続して初めて差別化になる。

機能アイデアの模倣は著作権の保護対象外だが、名称・UI 素材・コードの複製はしない。
データソースは商用利用と出所の明確さが必要。

## Decision（決定）

論文グラフ探索を次の形で実装する:

1. **データソースは OpenAlex**（CC0・キー不要・CORS 対応）。ブラウザから直接呼び、全リクエストに
   `mailto` を付ける（polite pool）。サーバーは追加しない
2. **類似度は書誌結合＋共引用の重み和**を候補プール内でクライアント計算する（純粋関数・決定論）
3. **探索は無料機能**とし、出口を「選択論文群を AI 設計（BYOK）の brief に引き渡す」に固定する。
   単体の論文探索ツールとしては売らない
4. 外部応答のパースは fail-closed（欠落・型不正は安全な既定値かエラー結果に写像し、例外を漏らさない）
5. 名称は Scoria 内の機能名（「論文グラフ」）とし、Connected Papers の名称・意匠は使わない

## Options Considered（検討した選択肢）

### 案1: OpenAlex 直呼び（採用）

- 長所: CC0 で商用制約なし・キー不要・CORS 対応を実測済み・運営コストゼロ（制約と完全整合）。
  参照/被引用がフィールドとして揃っており、バッチ取得（`filter=openalex_id:` OR 結合）が可能
- 短所: 引用データの網羅性は Semantic Scholar 比で分野差がある。共有レートプールなので
  リクエスト数の節度が必要（NFR-PERF-001 / NFR-OPS-001 で上限を規定）

### 案2: Semantic Scholar API（Connected Papers と同源）

- 長所: 引用グラフの品質が高い。推薦 API もある
- 短所: キーなし共有枠は実測で 429 頻発。キーはクライアント配布アプリに埋め込めず、利用者に
  もう 1 つの BYOK を要求するか、プロキシサーバー（運営制約違反）が要る。不採用

### 案3: 利用者の Anthropic キーで Claude に類似論文を挙げさせる

- 長所: 追加データソース不要
- 短所: 幻覚引用のリスクが本質的に排除できず、学術ツールとして致命的。実在論文の
  根拠付けにはグラフ側から実データを渡す方が正しい。不採用

## Consequences（結果）

- 得るもの: 運営コストゼロのまま探索→生成の一気通貫が完成し、AI 設計の brief に実在論文の
  書誌情報が入ることで幻覚引用対策にもなる。フリーミアムの「無料で価値・課金は生成側」構造を強化
- 失うもの: 引用データの網羅性は本家に劣る。オフラインでは使えない
- **再検討のトリガー**: OpenAlex のレート制限・CORS 方針が変わったら（プロキシ or キー対応を再検討）。
  探索利用が生成に繋がらないデータが出たら（出口設計を見直す）。課金導入時に探索の位置付けを再確認
