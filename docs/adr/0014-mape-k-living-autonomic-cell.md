# 0014: MAPE-K を「生きた自律細胞」へ — 恒常性・効き目フィードバック・膜・自己修復・安全状態

- Status: Proposed
- Date: 2026-07-22
- Deciders: （PR レビュアー）

## Context（背景）

MAPE-K 夜間セルフ改善（ADR-0010/0011）を「生きた自立した細胞的システム」に強化したい、という
要望を受け、多観点（自律成熟度／恒常性・効き目／膜・自己修復・DNA 完全性）で現状を診断した。判明:

- **休眠**: `knowledge/HEALTH.md` の推移表は cycle 2（2026-07-19）で停止。夜間 cron Routine は
  リポジトリ内に定義が無く、実際に周回していない（＝代謝していない）。Execute は LLM＋MCP を要すため
  **リポジトリ内だけで完全自己スケジュールは原理的に不可能**。
- **記憶喪失（最大の欠陥）**: `analyze.sh` は自分の実行台帳 `ledger.jsonl`（何を試して green/red/reverted
  だったか）を**一度も読まない**。K→A のフィードバック弧が切れており、reverted/赤の提案を毎晩同一に
  再生成する。唯一閉じているのは「人間が POLICY を編集する」ループのみ。self-CHOP スコアは
  自己最適化 0/3・自己修復 1/3・自己設定 1/3・自己防御 2/3。
- **膜の穴**: churn 由来のファイル名（ブランチに commit した者が中身を決められる外部制御データ）が
  無毒化されず、計画イシュー→**無人 Execute LLM** へ流れる（markdown/プロンプトインジェクション経路）。
- **恒常性なし**: setpoint/健全band が無く `gate_s` は無反応。実行の**効き目**（HEALTH の前後差）を測る
  機構が無い（PROGRESS の「効き目」列は散文のみ）。
- **自己修復なし**: circuit-breaker は暴走を**止める**が回復しない。1つの毒項目で全 Execute が凍結し
  手動 reset 待ち。knowledge/（＝細胞の DNA）の実行時検証が無い。**safe-state 未定義**（ISO 25010:2023
  の Safety が要件体系に未収録。PERSPECTIVES 記載）。

制約: ADR-0003（スタック非依存）／ADR-0004（ゲート単一入口・弱めない）／ADR-0013（純粋ロジックは
test-first）。既存ガードレール（main/秘密/課金に触れない・consult・PR-only・circuit-breaker）は**弱めない**。

## Decision（決定）

MAPE-K を、IBM 自律コンピューティングの **self-CHOP**（自己設定・自己修復・自己最適化・自己防御）＋
生物細胞の **恒常性(homeostasis)・膜(membrane)・安全状態(safe-state)** を満たす方向へ、
**決定論 Bash の小さな増分**で強化する。各増分は **test-first（ADR-0013）・1周1件・PR 単位**で、
既存の安全境界を弱めず**追加のみ**。ロードマップ（優先順）:

1. **膜/安全（先行）**: 外部制御シグナルの無毒化（本PRで実装済み）→ knowledge/ の**実行時**不変条件検査
   （fail-closed・単一ゲートに配線）→ 外部由来提案の provenance tier-floor（auto 禁止）。
2. **生きた核（フィードバック弧を閉じる）**: `analyze` が `ledger` を読み、reverted はスキップ／
   繰り返し赤は降格・機械が却下ログを追記 → POLICY の健全band(setpoint)で逸脱幅に比例した提案 →
   実行の効き目センシング（HEALTH 前後差の帰属＋回帰検知）。
3. **生存（自己修復）**: 全周期エントリ＋心拍・休眠自己検知（次セッションへ大きく通報）→ 項目隔離
   （全停止でなく毒項目のみ隔離）→ safe-state 定義（ADR＋NFR-SAFE＋`MAPE_SAFE` シグナルで危険時 Execute 抑止）。
4. **最適化（データが出てから）**: POLICY 重点テーマで再重み付け → トレンド微分感知 → 効き目に基づく
   有界な可変スコアリング（クランプ [0.7,1.2]・tier は不変）。

**順序と安全の原則**: 新シグナルは提案を**追加**または**tier 内で並べ替える**だけで、tier 分類
（consult/approve/auto）・無人 Execute の実行条件を**変えない**。効き目/トレンドはデータ希薄でも
graceful に劣化する（不明なら何もしない）。すべて `mape/tests/run.sh` で回帰検証する。

## Options Considered（検討した選択肢）

### 案1: 生きた細胞ロードマップを決定論 Bash の小増分で漸進導入（採用）

- 長所: 既存資産（M/A/P・circuit-breaker・knowledge・単一ゲート）を壊さず、self-CHOP を一段ずつ上げる。
  各増分が test-first で回帰保護でき、安全境界を弱めない。ADR-0003/0004/0013 に整合。休眠・記憶喪失という
  実診断に直接効く。
- 短所: 「完全自己スケジュール」は Execute が LLM を要すため達成できない（心拍＋休眠自己通報で代替）。
  多数の PR にまたがる。

### 案2: MAPE-K を大規模リライト（常駐デーモン/イベント駆動）で一気に自律化（不採用）

- 長所: 理論上の自律度は高い。
- 短所: スタック非依存の土台に常駐プロセス依存を持ち込む（ADR-0003 違反）。一度に安全境界を壊すリスク大。
  test-first の回帰保護が効かない。リポジトリの「1周1件・小さく安全に」の思想と衝突。

### 案3: 何も足さず cron を設定して現状のまま回す（不採用）

- 長所: 追加コストゼロ。
- 短所: 記憶喪失（K→A 断絶）・膜の穴・効き目未測定・自己修復なしのまま。回すほど同じ提案を再生成し、
  外部注入経路が無人 Execute に開いたまま。「生きた自律」の核心が未達。

## Consequences（結果）

- 得るもの: フィードバックで学習し（同じ失敗を繰り返さない）、恒常性で自己調整し、膜で無人実行を守り、
  効き目で自分の行動の成否を感じ、safe-state で危険時に安全側へ縮退する MAPE-K。self-CHOP の底上げ。
- 失うもの: 完全な自己スケジュールは不可（心拍＋休眠通報で代替）。増分ごとの実装コスト（test-first で相殺）。
- **再検討のトリガー**:
  - 効き目/トレンドの帰属がノイズ過多と判明したら、可変スコアリング（案4段）を neutral 固定へ縮小する。
  - 心拍・休眠通報でも周回が起きない（＝スケジューラ問題が本質）なら、外部 CI（GitHub Actions cron）等
    リポジトリ外の起動機構の是非を新 ADR で判断する。
  - いずれかの増分が安全境界を弱めていると監査で判明したら、その増分を revert し設計を見直す。
