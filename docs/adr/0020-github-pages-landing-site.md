# 0020: リポジトリ紹介の GitHub Pages ランディングを追加する（ブランチ配信・root）

- Status: Proposed
- Date: 2026-07-24
- Deciders: （PR レビュアー）

## Context（背景）

deb は Claude Code アプリ開発の土台であり、その価値（steering・品質ゲート・ADR・V字モデル・
MAPE-K 夜間セルフ改善）を短時間で伝える紹介面が無かった。README は網羅的だが、初見の来訪者に
「何をもたらす土台か」を一目で示すランディングが欲しい。デザインは複数案（アーティファクトで10案）
から高コントラストの技術文書調（Geist 路線・純白×純黒・モノスペースアクセント）を選定した。

制約: 絶対原則（main 直接コミット禁止・トピックブランチ＋PR）。ADR-0003（土台はスタック非依存）＝
ページ生成のためにビルドツールや特定フレームワークを土台へ持ち込まない。ADR-0004（品質ゲートの
単一入口）＝配信のために check.sh を迂回する仕組みを足さない。外部アセットに依存しない自己完結を保つ。

## Decision（決定）

**単一の自己完結した `index.html`（＋ `.nojekyll`）をリポジトリ root に置き、GitHub Pages を
「Deploy from a branch: `main` / `root`」で配信する。**

- ページは **1ファイル完結**。CSS は inline、フォントはシステムフォントのみ、図は CSS/インライン SVG。
  外部 CDN・Web フォント・画像を読み込まない（オフラインでも壊れない・サプライチェーン面も単純）。
- ビルド工程を持たない（静的 HTML を直接配信）。土台のスタック非依存（ADR-0003）を侵さない。
- `.nojekyll` を置き Jekyll 変換を無効化（素の静的サイトとして最短経路で配信）。
- テーマは OS 設定（`prefers-color-scheme`）に追従し、ヘッダのトグルで手動切替＋`localStorage` 保存。
- Pages の有効化はリポジトリ設定の操作（Settings → Pages）であり、コードでは行わない。公開 URL は
  `https://nigoh.github.io/deb/` を想定。

## Options Considered（検討した選択肢）

### 案1: root に静的 `index.html` を置きブランチ配信（採用）

- 長所: 最小構成。ビルド不要でスタック非依存を保つ。差分が1ファイルで追跡容易。CI（check.sh）に
  何も足さずに済む。GitHub Pages の既定経路で運用がシンプル。
- 短所: 来訪者から見た配信元がリポジトリ root（ソースと同居）。将来ページが増えると root が混む。

### 案2: `docs/` 配下を Pages ソースにする（不採用）

- 長所: サイト資材を1ディレクトリに集約できる。
- 短所: `docs/` は既に ADR・プロセス定義の置き場。Pages ソースにすると生の Markdown も配信対象に
  混ざり、意味づけが二重化する。既存構成への副作用が大きい。

### 案3: GitHub Actions で静的サイトをビルド／デプロイ（不採用）

- 長所: 将来 SSG（静的サイトジェネレータ）へ拡張しやすい。
- 短所: 現状は1ページで SSG は過剰。ワークフローとビルド依存を増やし、スタック非依存（ADR-0003）と
  「ゲート単一入口」（ADR-0004）の単純さを損なう。必要になってから移行すれば足りる。

## Consequences（結果）

- 得るもの: リポジトリの価値を一目で伝える公開ランディング。自己完結で保守が容易。土台の非依存性を
  維持したまま追加できる。
- 失うもの: root にサイト資材が同居する。Pages 有効化は手動設定が必要（コードでは完結しない）。
- **再検討のトリガー**:
  - ページ数が増える／多言語化・ブログ等が必要になった → SSG＋GitHub Actions 配信（案3）へ移行を新 ADR で検討。
  - サイト資材が root を圧迫する → `docs/`(案2) か専用ディレクトリへの集約を再判断。
  - デザインを刷新する → 本 ADR を supersede する新 ADR で方針を更新（選定経緯を残す）。
