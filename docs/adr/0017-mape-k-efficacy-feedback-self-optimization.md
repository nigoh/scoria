# 0017: MAPE-K の効き目フィードバック（self-optimization）— 台帳から学ぶ有界な採点調律

- Status: Proposed
- Date: 2026-07-22
- Deciders: （PR レビュアー）

## Context（背景）

ADR-0014 は MAPE-K を「生きた自律細胞」へ拡張するロードマップを置き、その最後の穴として
**自己最適化（self-optimization, IBM autonomic の self-Optimization）** を挙げた。細胞は自分の行動が
効いたかを覚え、効く行動を優先し効かない行動を控える。既存ループにはこの学習がなく、Analyze の採点
（`mape_score`）は毎回まっさらで、過去に何度も赤で回帰した種類の作業も、定着した作業も同じ重みだった。

素材はすでにある。Execute の各試行は委託台帳 `mape/state/ledger.jsonl`（green/red・committed＝夜を
またいで残る記憶）に残り、POLICY には「今月の重点テーマ」がある（ADR-0014 §自己設定・本リポジトリ §27）。
`mape_effectiveness_factor` は efficacy.tsv を読む口だけ先に用意され、データが無い間は中立（10）を返していた。
足りないのは **効き目データの生産者** と、それを採点へ安全に還元する結線である。

制約: ADR-0003（スタック非依存）/ ADR-0004（ゲート単一入口・弱めない）/ ADR-0010・0011（自律運用の
安全境界）/ ADR-0013（test-first）/ ADR-0014（追加のみ・既存境界を弱めない）。とりわけ **提案の tier
（consult/approve/auto）は自己最適化で決して変えない**（安全分類は `mape_classify` の純粋関数のまま）。

## Decision（決定）

MAPE-K に **効き目フィードバック（efficacy feedback）** を追加する。追加のみ・read-only・採点のみ。

- **生産者 `mape/efficacy.sh`**: 委託台帳の green/red を POLICY の重点テーマへ帰属させ
  （`mape_theme_of`。テーマに帰属しない実績はノイズ源として数えない）、テーマ別の効き目
  `efficacy.tsv`（`theme \t samples \t improved(green) \t worsened(red) \t status`）を書く。
  台帳は committed（持続する記憶）、efficacy.tsv は台帳から再計算できる派生物なので gitignore。
  パーサは python3→jq→（無ければ）フェイルセーフで中立（何も書かない）。破損行は無視して継続。
- **status 判定（保守的）**: `samples<3` は neutral（標本が薄いうちは断定しない）。`red==0` は improved
  （その種の仕事は定着している）。`red>=green` は worsened（回帰しがち）。それ以外は neutral。
- **消費者 `mape_effectiveness_factor`**: improved→係数 12（加点）、worsened→7（減点）、他→10（中立）。
  係数は **[7,12] にクランプ**し、`samples<3` は無条件で 10。Analyze の採点は
  `score = ((base + theme_boost) * factor + 5) / 10`（四捨五入）で合成する。`base=mape_score` は純粋・不変。
- **結線**: `run.sh` は A の前に `efficacy.sh` を走らせ efficacy.tsv を更新する（失敗しても中立で続行）。

**安全境界（NFR-OPT-001）**: 効き目は **採点（順位）だけ** に効く。tier を変えない・`mape_score` を汚さない・
標本 <3 は中立・係数は [7,12] に有界。これにより「効き目が暴れても危険な提案が auto へ格上げされる」
経路が構造的に存在しない。効き目は POLICY の重点テーマに帰属した実績のみから学ぶ（帰属しない作業は無風）。

## Options Considered（検討した選択肢）

### 案1: 台帳の green/red 比をテーマへ帰属させ、有界クランプで採点のみ調律する（採用）

- 長所: 学習の素材が既存の committed 台帳だけで済み、夜をまたいで持続する。因果を誇張しない
  （HEALTH 個別指標への強引な帰属をせず、「その種の作業が定着したか」という観測可能な事実だけを使う）。
  係数 [7,12]・標本 <3 中立・tier 不変で、暴走しても採点順位の小さな揺れに閉じる。read-only・追加のみで
  ADR-0003/0004/0013/0014 に整合。test-first で回帰保護でき、パーサ欠落時も中立。
- 短所: テーマに帰属しない作業は学習対象外（POLICY のテーマ設定に依存）。green/red 比は「定着したか」で
  あって「HEALTH をどれだけ改善したか」の直接測定ではない（近似）。

### 案2: 各 Execute で HEALTH 指標のスナップショットを台帳に載せ、実装前後の指標差で効き目を測る（不採用）

- 長所: 「TODO を 5→2 に減らした」のような指標改善を直接測れる。
- 短所: テーマ（例「セキュリティ」）を単一 HEALTH 列へ帰属させる問題が本質的に曖昧（帰属の恣意）。
  台帳スキーマ拡張が必要で、危険な `circuit-breaker.sh record`（GLOBAL 暴走の最終防壁）へ手を入れる。
  相関を因果と誤認しやすい（同時に動いた他要因を切り分けられない）。複雑さに見合う確度が出ない。

### 案3: 効き目で tier を動的に上げ下げする（強い自己最適化）（不採用）

- 長所: 「効くテーマは auto で速く回す」など最適化の効き幅が大きい。
- 短所: 安全分類（consult/approve/auto）を学習が動かすと、危険な提案が無人実行へ格上げされる経路が
  生まれる。ADR-0010/0011 の安全境界と真っ向から反する。自己最適化は速さより安全性に劣後させるべき。

## Consequences（結果）

- 得るもの: ループが「自分がどの種類の仕事に効いているか」を committed 台帳から学び、効くテーマの提案を
  わずかに前へ、回帰しがちなテーマを後ろへ回す。ADR-0014 の self-optimization の穴を、tier を触らない
  有界な採点調律として塞ぐ。効き目が薄い/未知のうちは自動的に中立で、従来挙動を変えない。
- 失うもの: green/red 比は効き目の近似（指標改善の直接測定ではない）。POLICY にテーマが無いと学習は無風。
  efficacy.tsv は派生物なので証跡には残らない（根拠は committed 台帳を辿る）。
- **再検討のトリガー**:
  - 近似（green/red 比）が実際の健全性改善と乖離すると判明したら、案2（指標スナップショット）の
    部分導入を新 ADR で再検討する。
  - 係数 [7,12] の幅が小さすぎて効き目が採点に現れない／大きすぎて順位が暴れると分かったら、幅と
    しきい値（samples>=3・red>=green）を POLICY で調律可能にする拡張を検討する。
  - 効き目で tier を動かしたい運用要求が出たら、案3の安全な部分集合（例: auto→approve の格下げのみ
    許し格上げは禁止）を新 ADR で判断する。
