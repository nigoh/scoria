# 0030: 製品の焦点を「研究ソフトウェア開発（RSE）」に定める

- Status: Proposed
- Date: 2026-08-14
- Deciders: リポジトリオーナー / Claude

## Context（背景）

Scoria はこれまで「学術研究の手順（文献レビュー・メタ分析等）」を Claude Code 拡張にする
ジェネレータだった。しかし Claude Code の主ユーザーは開発者であり、文献手順のテンプレートは
利用面の接点が細い。オーナーの意向は「ソフトウェアに特化したい。ただし学術的なソフトウェア」。
学術と開発の交点＝**研究ソフトウェア工学（Research Software Engineering）**には、
再現性・データ来歴・引用可能なリリースなど固有の実務があり、汎用開発ツールが埋めていない。

## Decision（決定）

製品の対象を**研究ソフトウェアの開発**（解析コード・データパイプライン・研究用パッケージ）に
定め、既存の文献手順テンプレートは**全面的に置き換える**。

1. テンプレートは 4 領域 7 種＋カスタム: 再現性コードレビュー / 数値・データ処理のテスト設計
   （コード品質）、README・引用整備 / データ・パイプライン文書化（ドキュメント）、
   実験の再現実行 / リリース・DOI アーカイブ（運用）、ラボ開発規約・オンボーディング（チーム開発）
2. AI 設計（ADR-0027）のペルソナを「研究ソフトウェア工学に精通した設計者」に転換し、
   再現性・検証可能性・データ来歴を設計原則に据える
3. **論文グラフ探索（ADR-0028）は存続**する。手法論文・ソフトウェア論文の探索は研究ソフトウェア
   開発の入力そのものであり、新ポジショニングと整合する
4. LP・文言・メタ情報を新ポジショニングに揃える。ウィザード・生成機構・BYOK の構造は変えない

## Options Considered（検討した選択肢）

### 案1: 研究ソフトウェア工学（RSE）特化（採用）

- 長所: 学術資産（論文グラフ・研究文脈のプロンプト）が活きる。汎用 SE ツールとの差別化が明確。
  対象ユーザー（研究者・RSE・大学院生）が既存ポジショニングと連続していて転換コストが低い
- 短所: 純粋な SE 市場より母数は小さい

### 案2: 汎用ソフトウェア開発特化

- 長所: 市場最大。Claude Code ユーザーの中心
- 短所: 競合が濃く（既製スキル集・公式サンプル多数）、論文グラフなど既存資産が死ぬ。
  「何でも屋のテンプレ集」は BYOK 課金の根拠が弱い

### 案3: 学術研究とソフトウェア開発の 2 ドメイン切替

- 長所: 既存資産を全部残せる
- 短所: UI・テンプレ・文言・テストが二重化し、小規模運営の保守限界を超える。焦点も濁る

## Consequences（結果）

- 得られるもの: 明確な差別化軸（再現性×Claude Code）、既存機能（グラフ・BYOK）との一貫した物語
- 失うもの: 文献手順テンプレート（git 履歴には残る）。既存利用者の生成履歴は localStorage 内で
  引き続き閲覧可能だが、旧テンプレート ID の再編集はカスタム扱いになる
- **再検討のトリガー**: RSE 文脈の利用が伸びず汎用 SE 需要が支配的になったら案2を再検討する。
  Stripe 課金導入時に対象ユーザーの支払い意思が確認できなければポジショニングを見直す
