# 要件仕様: 論文グラフ探索

- 責任者: 要求元=リポジトリオーナー / 実装責任=Claude / 検証責任=Claude
- 関連 ADR: ADR-0028
- 対象: 種論文から引用関係（共引用・書誌結合）で類似論文を集めてグラフ表示し、
  選んだ論文群を AI 設計（ADR-0027）の brief に引き渡す機能。データソースは OpenAlex（CC0）
- 重要度: 中（認証・課金・個人情報を扱わない。外部 API 応答のパースはエッジ多発コードとして
  敵対的テスト必須。`.claude/rules/tdd.md`）
- 合意記録: 会話でスコープ合意（検索 → 種論文選択 → 類似グラフ → brief へ送る。単体クローンではなく
  AI 設計への接続を差別化とする）。PR で最終合意

## 機能要件

### REQ-GRAPH-001: キーワードで論文を検索できる

- 優先度: 高
- ユーザーストーリー: 研究者として、キーワードやタイトルで種論文を探したい。
  なぜなら手元に DOI や ID がなくても出発点を決めたいから
- 受入基準（Acceptance Criteria）:
  - Given 検索語 When 検索リクエストを構築する Then OpenAlex works API の検索 URL になり、
    表示に必要なフィールドだけを `select` で要求する
  - Given 検索応答 When 正規化する Then タイトル・年・著者・被引用数を持つ候補一覧になり、
    欠落フィールドは安全な既定値（空文字・0・空配列）に落ちる
  - Given 空白のみの検索語 Then リクエストは発行されず空結果を返す
- 対応テスト: `Verifies: REQ-GRAPH-001`（`src/lib/graph/openalex.test.ts`）

### REQ-GRAPH-002: 種論文の引用近傍を収集する

- 優先度: 高
- ユーザーストーリー: 研究者として、種論文の参照文献と被引用論文から候補プールを得たい。
  なぜなら類似論文は引用の近傍に集中するから
- 受入基準（Acceptance Criteria）:
  - Given 種論文 When 近傍を収集する Then 参照文献（referenced_works）と被引用論文（cites フィルタ）
    が候補プールに集まり、候補数は上限（200 件）で打ち切られる
  - Given 参照文献の ID 群 When 詳細を取得する Then 1 リクエストあたり最大 50 件のバッチ
    （`filter=openalex_id:` の OR 結合）にまとめられる
  - Given 収集済みプール Then 種論文自身は候補から除外され、重複 ID は 1 件に畳まれる
- 対応テスト: `Verifies: REQ-GRAPH-002`（`src/lib/graph/openalex.test.ts` / `neighborhood.test.ts`）

### REQ-GRAPH-003: 引用関係から類似度を計算する

- 優先度: 高
- ユーザーストーリー: 研究者として、単なる引用の有無ではなく「同じ文献を引く・同じ論文に引かれる」
  度合いで近さを知りたい。なぜならそれが主題の近さをよく表すから
- 受入基準（Acceptance Criteria）:
  - Given 2 論文の参照リスト When 類似度を計算する Then 書誌結合（参照の共通数）と
    共引用（同時に引かれた数）の重み和になり、値は 0 以上
  - Given 参照が全く重ならない 2 論文 Then 類似度は 0
  - Given 同一入力 Then 結果は常に同一（決定論）で、順位の同点は ID の辞書順で安定に並ぶ
  - Given 自分自身との組 Then 類似度計算の対象にしない
- 対応テスト: `Verifies: REQ-GRAPH-003`（`src/lib/graph/similarity.test.ts`）

### REQ-GRAPH-004: 類似グラフを構築する

- 優先度: 高
- ユーザーストーリー: 研究者として、候補全部ではなく類似度上位の見通せる規模のグラフが欲しい。
  なぜなら数百ノードの毛玉は読めないから
- 受入基準（Acceptance Criteria）:
  - Given 候補プールと類似度 When グラフを構築する Then ノードは種論文＋類似度上位（最大 40 件）、
    エッジは類似度が閾値を超える組だけになる
  - Given 構築済みグラフ Then 種論文ノードは必ず含まれ、孤立した候補ノードは種論文と最低 1 本の
    エッジで結ばれるか除外される
  - Given 空の候補プール Then 種論文のみのグラフになる（例外で落ちない）
- 対応テスト: `Verifies: REQ-GRAPH-004`（`src/lib/graph/build.test.ts`）

### REQ-GRAPH-005: グラフを表示して論文を選択できる

- 優先度: 中
- ユーザーストーリー: 研究者として、グラフ上で論文をクリックして候補に入れたり外したりしたい。
  なぜなら視覚的な近さを見ながら文献リストを組みたいから
- 受入基準（Acceptance Criteria）:
  - Given 構築済みグラフ When 画面に表示する Then ノードは力学レイアウトで配置され、
    種論文は視覚的に区別される
  - Given ノード When クリックする Then 選択状態がトグルし、選択一覧（書誌情報つき）に反映される
  - Given 検索・収集の進行中 Then 進行中表示が出て、失敗時はエラーメッセージが表示される
- 対応テスト: `Verifies: REQ-GRAPH-005`（`e2e/graph.spec.ts`。API はモック）

### REQ-GRAPH-006: 選択した論文群を AI 設計の brief に引き渡す

- 優先度: 高
- ユーザーストーリー: 研究者として、選んだ論文リストをそのまま拡張生成の入力にしたい。
  なぜなら探索の成果が Claude Code 拡張という成果物になることがこの機能の目的だから
- 受入基準（Acceptance Criteria）:
  - Given 選択論文群 When brief 用に整形する Then 各論文はタイトル・著者・年・OpenAlex ID を含む
    引用行になり、実在しない情報は補われない（欠落は欠落のまま）
  - Given 整形済みテキスト When ビルダーへ引き渡す Then ウィザードは AI 設計モード・brief 入力済みの
    状態で開く
- 対応テスト: `Verifies: REQ-GRAPH-006`（`src/lib/graph/brief.test.ts` / `e2e/graph.spec.ts`）

### REQ-GRAPH-007: DOI で種論文を直接指定できる

- 優先度: 中
- ユーザーストーリー: 研究者として、手元にある論文の DOI をそのまま貼って出発点にしたい。
  なぜなら読んでいる論文から探索を始めるときはキーワード検索より確実だから
- 受入基準（Acceptance Criteria）:
  - Given DOI（`10.…/…` 形式・`https://doi.org/…` URL・`doi:` 接頭辞のいずれか）When 正規化する
    Then 素の DOI（`10.…/…`）になり、DOI でない入力は null と判定される
  - Given 正規化済み DOI When 検索欄に入力して検索する Then キーワード検索ではなく OpenAlex の
    単一 work 取得（`/works/doi:…`）が発行され、該当論文が候補一覧に 1 件表示される
  - Given 存在しない DOI（404）Then 見つからない旨のエラー結果になる（例外で落ちない）
- 対応テスト: `Verifies: REQ-GRAPH-007`（`src/lib/graph/openalex.test.ts`）

### REQ-GRAPH-008: グラフのノードから再探索できる

- 優先度: 中
- ユーザーストーリー: 研究者として、グラフで見つけた論文を新しい種にして探索を続けたい。
  なぜなら文献調査は 1 ホップでは終わらず、芋づる式にたどるものだから
- 受入基準（Acceptance Criteria）:
  - Given 表示中のグラフ When ノードをダブルクリックする Then その論文を種とした近傍収集が走り、
    グラフが新しい種のもとで組み直される
  - Given 再探索の前に選択していた論文 Then 選択は維持され、新しい種が選択に加わる
    （ホップをまたいで文献リストを積み上げられる）
- 対応テスト: `Verifies: REQ-GRAPH-008`（`e2e/graph.spec.ts`）

| 保守性 | — | | 対象外: リポジトリ全体の品質ゲート（check.sh）で担保済み |
| 移植性 | — | | 対象外: 対応ブラウザは既存アプリと同一 |
| 運用性 | NFR-OPS-001 | すべての OpenAlex リクエスト URL に `mailto` パラメータを付与する（polite pool。根拠: OpenAlex の推奨。無指定プールはレート制限が不安定） | |
